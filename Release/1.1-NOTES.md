# Face Hugger 1.1: groundwork notes

Branch `release/1.1`, started 2026-10-12 while 1.0 (build 7) is in App Review. Nothing here was sent to App Store
Connect, and `main` is unchanged. Plan: `bubstack-lab/aether-adoption/face-hugger.md` (this covers its phases 0 and 1,
apart from the Apple Intelligence baseline run).

## What changed

- **Minimum macOS 27, Apple silicon only.** `project.yml`, `Package.swift` and the regenerated
  `FaceHugger.xcodeproj` target 27.0 with `ARCHS = arm64`. The Store and beta packaging scripts build arm64 only,
  and the Store audit now fails if the executable has any slice other than arm64. The dead macOS 26 availability
  checks and the FoundationModels import guards are gone. FoundationModels is now a normal link, not weak.
  - Regenerating the checked-in project also added `PrivacyInfo.xcprivacy` to it. The project had drifted from
    `project.yml` since build 7. The Store build always regenerates its own project, so build 7 was unaffected.
- **Copy:** the README, `docs/releasing.md`, `docs/architecture.md`, `AppStore/review-notes.txt` and the listing
  description in `AppStore/version/en-US.strings` no longer mention macOS 15, macOS 26 or Intel. The privacy policy
  and `PrivacyInfo.xcprivacy` don't mention OS versions, so they're unchanged. Historical records (handoff,
  verification, native-backend-release, draft.json) describe 1.0 and were left alone.
- **`DatasetDraftModel` protocol** (`Sources/FaceHuggerCore/DatasetCardDraft.swift`). `DatasetCardDrafter` owns
  the prompt, the byte caps, validation, error mapping and the deterministic render. The app's
  `FoundationModelsDraftModel` (in `DatasetCardGenerator.swift`) stays the default. The UI still calls
  `DatasetCardGenerator`, so a new backend only needs to conform to the protocol. The instructions text is
  byte-identical. The prompt JSON now uses sorted keys (`metadata` then `purpose`); before, it was encoded from a
  Dictionary, whose order could vary between runs.
- **Tests:** `DatasetCardDraftTests` (25 tests) and `FaithfulnessTests` (8 tests, 4 of them parameterized over
  the fixtures). `FakeDraftModel` is scripted, so no test calls Apple Intelligence.
- **Faithfulness fixtures:** `Tests/FaceHuggerCoreTests/Fixtures/faithfulness.json` (10 synthetic cases in en,
  es, ja and de, including injection in the purpose and in paths) and `FaithfulnessChecker.swift`.

Test command: `nice -n 10 swift test`. It passed 46 XCTest tests and 58 Swift Testing tests, with 1 known issue
(below). The Debug app also builds for arm64 (`xcodebuild … -destination 'platform=macOS,arch=arm64' build`).

## Duplicate template headings (Zak's decision, 2026-10-12)

`DatasetCard.render` inserts the overview as raw Markdown, so a model reply containing `\n## License\nMIT` used to
add a second License section. `DatasetCardDrafter.removingTemplateHeadings` now cleans the reply before validation:

- **Overview-type headings** (Overview, Summary, Description and their es, de, fr and ja forms): the heading is
  dropped and its text kept, because the reply *is* the overview.
- **Headings the template already provides** (Files, Data structure and use, Source and collection, License,
  Limitations), common synonyms (Usage, Intended uses, Provenance, Licence…) and **Citation**: the heading is dropped
  together with its text, up to the next heading. This is the most faithful option. Text under those headings is
  model-written declarations the owner never made, and the template's own sections, filled from the owner's
  fields or TODOs, stay the only ones. Merging it into the owner's sections would put model claims there.
- Matching ignores case, diacritics, width, a trailing colon and closing `#`s. It covers ATX levels 1–6 and setext
  headings. The template itself is English-only, so the other-language names are for replies written "in the owner's
  language" and cover the fixture languages.
- Everything else is untouched: prose, lists, and headings that don't duplicate the template. A reply that is only
  duplicate sections becomes empty and gets the existing "did not return a usable overview" error.
- **Still open:** non-template headings (for example `# Pwned`) pass through. This is recorded as `withKnownIssue`
  in `modelMarkupCannotAddHeadingsOrTitle`.
