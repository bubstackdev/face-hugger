# Version 1.1 foundation verification

October 27, 2026. The first development slice implements typed attempt recording and durable receipt history. The [implementation plan](../plan-1.1.md#implementation-status) tracks the remaining work.

## Implemented behavior

- Native callbacks are reduced synchronously in one serialized recorder. The UI samples typed snapshots instead of spawning a task for every event or translating events through JSON lines. Job/attempt IDs and sequence guards reject stale, repeated, and out-of-order reductions.
- An attempt is saved before upload execution. Acknowledged commits are saved before the uploader writes its local recovery checkpoints. Later failure or interruption preserves those acknowledgements. Relaunch marks unfinished attempts interrupted without inventing an end time or a successful outcome.
- Receipts retain raw reported progress and canonical commit links. These byte counts describe the existing uploader's file-content accounting; they are not a measurement of all wire traffic or retransmissions. Phase, rate, and retry presentation remain later work.
- Transfer history shows outcomes across attempts, supports copying and commit/repository links, and survives queue-item removal. Clear history keeps the active attempt, queue items, recovery checkpoints, and remote files. Retention is 200 terminal receipts; each keeps the latest 20 commit references plus total acknowledged counts.
- Legacy queue outcomes are imported once with unknown metrics left unknown. Unsupported or unreadable history is not overwritten; failed persistence prevents starting an upload or stops further work. Receipts contain neither source bookmarks nor absolute source paths, credentials, signed provider URLs, file contents, or raw error bodies.
- The Hub client retains Git blob, LFS content, and opaque Xet identities separately. Revision-scoped tree APIs and parent-guarded commits have fixture coverage. These capabilities are preparation for reviewed plans; the existing uploader does not yet use a reviewed action set or the new parent-guarded overload.

`Scripts/check.sh --build` passed on the development Mac:

The new coverage includes lifecycle ordering and concurrency, duplicate and stale events, partial commit recovery, idempotent finalization, retrying a failed final write, one-time legacy migration, history clearing and retention, bounded logs, safe receipt contents, archive version refusal, write failures, revision pagination, identity parsing, parent guards, and malformed commit acknowledgements.

The check log is retained locally at `.build/one-one-check.log`. Xcode emitted the existing informational warning that App Intents metadata extraction was skipped because the app does not depend on AppIntents.

An isolated preview of the actual receipt SwiftUI component was rendered with a synthetic failed attempt and a confirmed partial commit. Its text wrapping was inspected. Preview files and synthetic history are under `.build/one-one-preview/`; the preview did not load the real app's queue, Keychain credentials, or remote data. This is separate from native interaction and sandbox qualification.

The HTTP fixtures follow the official Hub client's [tree identity parsing](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/hf_api.py) and [commit header construction](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/_commit_api.py), inspected on October 27. No live Hub mutation was performed for this slice.

## Remaining validation and implementation

Full signed sandboxed UI interactions, real application stop/quit/relaunch cycles, older macOS and Intel execution, and exact Release installer audits remain release gates. A valid Debug build does not establish those behaviors.

The next slice adds the disk-backed complete upload plan, supported content comparisons, stale-plan review, and guarded execution. Empty/new-repository planning, phase/rate/retry reporting, pairing polish, and Dock entry remain pending. Aether Kit migration remains independent.
