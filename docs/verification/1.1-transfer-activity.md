# Version 1.1 transfer activity verification

October 27, 2026. This slice adds phase, throughput, and retry visibility to the [reviewed upload workflow](1.1-upload-review.md). Remaining work is tracked in the [implementation plan](../plan-1.1.md#implementation-status).

## Behavior and measurements

Review reports validation, scanning, hashing, comparison, and verification phases. Approved execution also reports negotiation, upload, and commit phases. The transfer shelf shows the current file when available. Retry waits show a fixed reason category, the next request attempt and limit, and a countdown. Stop remains available during waits; cancelling review stops its requests and removes its unapproved plan when the operation settles.

Logical file progress is separate from transport observations. Request-body totals count observed metadata, file, and encoded commit bodies across explicit attempts. A second total includes only file/commit bodies. A retried multipart part can therefore increase observed body bytes beyond the source size without increasing logical file progress beyond that size. These totals exclude headers and transport overhead and do not claim to measure TCP retransmissions or bytes accepted remotely.

URLSession data-backed uploads make inline commit bodies observable alongside file-backed LFS uploads. Intermediate and final actual byte counts feed a per-request-attempt high-water mark; duplicate, decreasing, and stale callbacks cannot add bytes twice. No total is inferred from an expected body length. File/commit-body speed uses monotonic time and at most 64 samples around a five-second window, requires at least 250 ms of observations, and disappears after two idle seconds or on request completion, phase suspension, retry wait, or terminal outcome. Small requests may finish without displaying a rate. No overall ETA is invented.

Request eligibility remains bounded to three attempts for existing retryable requests. Production backoff is one then two seconds, combined with a Retry-After integer or HTTP date capped at 30 seconds. Authentication/permission failures and conflicts do not retry. Commit requests and multipart completion are not automatically retried. A retry wait and a retry actually started are counted separately.

Receipts retain raw transport totals, retry counts/reasons, and last observed phase/time. Retry control transitions checkpoint these summaries; terminal outcomes and confirmed commits also persist them. A crash can lose observations since the last checkpoint. Live rates, current file names, request IDs, and countdown deadlines are excluded. Existing archives decode with new measurements unknown. An unfinished receipt remains interrupted after restart, without an invented finish time.

## Validation

`Scripts/check.sh --build` completed successfully:

| Check | Result |
| --- | --- |
| Swift XCTest | 57 passed |
| Swift Testing | 65 passed |
| Combined Swift suite | 122 passed |
| Historical Python suite | 56 run, 3 skipped, no failures |
| Native Mac Debug app | Built with macOS 15 deployment target |

Thirteen new tests cover duplicate/decreasing/stale callbacks, partial network sends, multipart retries, logical versus body-byte counts, metadata separation, inline commit encoding, bounded retry exhaustion, nonretryable mutations and authorization failures, Retry-After forms, cancellation during a 30-second wait, idle rate expiry, integer saturation, restart persistence, terminal cleanup, and old archive decoding.

A real URLSession loopback smoke test sent synthetic 65,536-byte data-backed and 2,097,152-byte file-backed request bodies. Server-received lengths and delegate-observed totals matched for both. This checks native callback plumbing without Hub credentials or remote mutations. It does not establish live service behavior or internet transfer performance.

The actual activity SwiftUI component was rendered and inspected in light and dark appearances with synthetic active-upload and rate-limit-wait data, including a long path. The full app was compiled; this component preview does not replace an interactive sandboxed test. No real queue or Keychain state was loaded by the preview.

Local evidence is in `.build/transfer-activity-check.log` and `.build/transfer-activity-preview/` (render harness/images and loopback harness/log). The existing App Intents metadata-extraction warning reflects the lack of an AppIntents dependency.
