# Version 1.1 upload review verification

October 27, 2026. This slice connects complete on-disk review plans to explicit approval and guarded execution. The [implementation plan](../plan-1.1.md#implementation-status) tracks subsequent work; the [foundation record](1.1-foundation.md) covers the earlier receipt and event changes.

## Implemented workflow

Review upload builds a private SQLite inventory for the full filtered source folder. The preview limit does not limit planning, and the review table reads bounded pages. Source hashing and mutation checks are shared with the legacy uploader while retaining its checkpoint encoding. Review requests remote account/repository metadata but performs no preupload negotiation, object upload, or commit.

The plan distinguishes additions, replacements, identical content, exclusions, unknown comparisons, and conflicts. Git blob SHA-1 and SHA-256 identities use the Git blob header; LFS identities use raw content SHA-256. Opaque Xet identifiers and missing metadata remain unknown. A conflicting remote file marks every blocked included descendant. Unknown comparisons require an explicit acknowledgement before approval.

The approved queue item records its plan ID. Execution checks the source, account, visibility, exact route/filters, and expected head before transfer. Only planned rows are executed. Each batch uses the parent-commit precondition; acknowledged batches update the plan's expected head and completed paths together. Partial resume skips those paths only at the expected head. Foreign or ambiguous commits require a fresh review and do not trigger an automatic commit replay.

All-identical runs complete with zero negotiations, object uploads, and commits. Their receipts retain the verified revision without inventing a commit acknowledgement. Repository ignore decisions are recorded separately during approved execution. Existing jobs without a plan first open review; reviewed jobs can explicitly be reviewed again. Current repository visibility is shown by a fresh review and bound into the approved job.

Repositories with no confirmed revision show a blocked review and never use an unguarded initial commit. Supporting that case requires verification of the service's initial-commit precondition. An initialized repository with a confirmed revision and no remote files is supported.

## Automated validation

`Scripts/check.sh --build` covers the following:

| Check | Result |
| --- | --- |
| Swift XCTest | 52 tests passed |
| Swift Testing | 57 tests passed |

| Native Mac Debug app | Built with the macOS 15 deployment target |

Nineteen upload-plan tests cover:

- Git and LFS identity, a separately calculated Git SHA-256 fixture, unknown/opaque metadata, exclusions, and binary UTF-8 path matching.
- Complete planning beyond the 2,000-row preview limit with a 2,105-file fixture and bounded pages.
- File/folder conflicts, failed or moved remote comparisons, no-revision refusal, and cancellation cleanup.
- Explicit approval, changed source/route/account/visibility/revision refusal, added files, and mutation during transfer.
- Exact inline and empty-file bodies, ignored files without commits, acknowledged partial recovery, parent guards, and refusal to replay foreign or ambiguous commits.
- A fresh review's use of current visibility and durable verified-revision receipts for all-identical runs.

The final local log is `.build/upload-review-check.log`. The build's App Intents metadata-extraction warning reflects the existing lack of an AppIntents dependency.

## UI inspection and remaining gates

The actual review SwiftUI component was rendered in light and dark appearances with a local synthetic inventory and a mock Hub. Inspection covered action counts, content estimates, file rows, conflict explanations, pagination controls, the unknown-content acknowledgement, and a disabled approval action for conflicts. Preview inputs and images are under `.build/upload-review-preview/`; no real queue, credentials, or remote files were used.

No live Hub mutation was performed. Full signed sandboxed interactions, real stop/quit/relaunch behavior, older macOS and Intel execution, and exact Release installer audits remain release gates. This record does not replace them. Phase/rate/retry presentation was subsequently implemented in the [transfer-activity slice](1.1-transfer-activity.md); pairing polish and Dock entry remain pending.
